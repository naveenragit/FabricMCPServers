MCP server 2 · T-SQL over the lakehouse

OneLake SQL MCP

Hands the agent raw lakehouse tables over T-SQL. No measures or relationships: it writes every join and calculation.

servers/onelake-sql-mcp
Tools the agent uses
get_database_schema

Every allowlisted table with its columns, SQL types and nullability.

  • no arguments
  • no keys or measures
execute_sql

Runs one read-only T-SQL query and returns the rows.

  • SELECT / WITH only
  • ≤ 1,000 rows
  • 60 s

The read-only check strips comments and literals, allows one statement, and rejects write keywords such as INSERT, DROP and EXEC.

Takeaways
  • Close overall. The agents are within 5 points. No gap is clearly beyond chance; SQL vs Fabric is borderline (95% interval 0 to +10).
  • SQL is fastest and best or tied on Tiers 1–3. DAX leads on the multi-step Tiers 4–5.
  • Fabric uses the fewest agent tokens but is 4–5× slower, and scores lowest on Tier 5.
  • Safety: no write, secret, tool or injection failures on any arm. Gate failures (DAX 8, Fabric 8, SQL 0) were mostly bulk client lists and identity transparency.
  • Never right on any arm: Q20, Q33, Q50, R38. These are candidates for a criteria review.
